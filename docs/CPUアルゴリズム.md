# CPUアルゴリズム

対応バージョン: ルール v1.6(実装に追従して更新するドキュメント。版は固定しない)

CPU対戦AIの判断ロジックをまとめる。調整(閾値の変更・難易度追加)や新カード対応の際は、本ドキュメントと実装を併せて更新すること。

## 1. 概要

| 項目 | 内容 |
|---|---|
| 実装ファイル | `frontend/src/engine/cpu.ts`(行動判断)/ `frontend/src/engine/cpuDeck.ts`(デッキ構築) |
| 呼び出し元 | `frontend/src/store/gameStore.ts` の `pump` ループ(CPUの手番・pendingを1手750msずつ進める) |
| 構造 | 状態を持たない純粋関数の集合。`GameState` と難易度を受け取り、1回の呼び出しで1アクションを返す |
| 難易度 | `easy` / `normal` / `hard` の3段階。同じ関数内で分岐する |

ゲームエンジンの pending 機構(割り込み待ち)に対応する関数が1対1で用意されている。

| エントリポイント | 役割 | 対応する局面 |
|---|---|---|
| `buildCpuDeck` | 40枚から20枚デッキを自動構築 | 対戦開始前 |
| `nextMainAction` | メインフェイズの次の1手 | 自分のメインフェイズ |
| `nextAttack` | 攻撃宣言(or 攻撃終了) | 自分のバトルフェイズ |
| `decideBoost` | 攻撃側の戦闘強化 | pending: `attackerBoost` |
| `decideReaction` | 防御側の罠 or 強化 | pending: `defenderReaction` |
| `decideTrap` | 召喚トリガー罠の発動判断 | pending: `trapPrompt` |
| `decideTarget` | 効果対象の選択 | pending: `effectTarget` |

CPUは公開情報のみで判断する(相手の手札の中身や伏せ罠の種類は見ない。枚数と、効果で確認済みの伏せのみ参照する)。

## 2. デッキ自動構築(`cpuDeck.ts`)

開封した40枚から20枚を選ぶ。CPU戦のCPUデッキと、デッキ構築画面の「おまかせ構築」(`buildDeckIndices`)で共用。

構成の目安:

| 枠 | 枚数 | 選定基準 |
|---|---|---|
| 低星モンスター(★1〜3) | 8枚 | リリースの起点と序盤の壁 |
| 中星モンスター(★4〜5) | 3枚 | スコア順 |
| 高星モンスター(★6以上) | 2枚 | スコア順 |
| 魔法・罠 | 残り(約7枚) | SPELL_SCORE順 |
| 補充 | 不足分 | 残りのモンスターからスコア順 |

- モンスター評価式: `攻撃力 + 守備力×0.3 + レアリティボーナス(N:0 / R:100 / SR:200 / UR:300)`
- 魔法・罠の優先度(SPELL_SCORE)は除去を最優先: 天罰(10)> アイギスの盾(9.5)> 鬼退治・落とし穴(9)> 強制送還・金縛り(8)> 神隠し(7.5)> 黄泉返り(7)> 神便鬼毒酒(6.5)> 払い清め・背水の陣(6)> 砂かけ婆(5.5)> 死者の声・人魚の肉(5)> 草薙剣・軍配(4)> お焚き上げ(3)

## 3. メインフェイズ(`nextMainAction`)

優先順位は固定: **①魔法(除去・回復)→ ②召喚 → ③バフ魔法 → ④罠セット → 終了**。各ステップで条件を満たす最初の1手を返す。

### 3.1 魔法の発動条件

手札を順に走査し、カードごとの条件で判断する。「相手最強」は相手フィールドの実効攻撃力最大のモンスター。

| カード | 発動条件 |
|---|---|
| 天罰(UR4) | v1.6でお互い全破壊のため逆転札として運用。易: 相手の体数が自分以上なら使う。普通・難: 相手の合計攻撃力が自分+1500以上 or 体数差2以上 |
| 鬼退治(SR9)・強制送還(R09) | 相手最強を対象に。易: 無条件。普通・難: 自軍最強で勝てない相手 or 攻撃力2000以上のみ |
| 神便鬼毒酒(N27) | 普通・難のみ。-700で自軍最強が相手最強を上回れる時、または相手最強が2800以上 |
| 払い清め(N21) | 伏せがあれば使う。確認済みの危険な罠(アイギス/落とし穴/金縛り)を優先、なければ先頭 |
| 人魚の肉(R10) | ライフが閾値以下(易: 6000 / 普通・難: 4000)。v1.6で回復量2500 |
| 死者の声(N22) | 相手モンスターがいる時、墓地から守備力最大を壁として釣る |
| 黄泉返り(SR7) | 墓地の攻撃力最大を蘇生(易: 1000以上 / 普通・難: 1500以上) |
| お焚き上げ(N29) | 難のみ。手札に鬼火があり、攻撃可能な攻撃表示モンスターがいる時(2ターン目以降) |

### 3.2 召喚(`decideSummon`)— 1ターン1回

**通常召喚の最良**(出せる中で攻撃力最大)と**ぴったりブースト召喚の最良**を比較して決める。

- ブースト候補の評価(普通・難のみ): `純益 = 召喚するカードの攻撃力 − リリースの損失`
  - リリース損失: 場のモンスター = 実効攻撃力 / 手札 = 攻撃力×0.8(手札に温存する価値ぶん割引)
  - 可変星を含む全リリース候補をエンジンの `releaseOptionsFor` で列挙する。v1.5以降、手札からのリリースは供物モンスター(豆狸・人魚姫・一反木綿)のみエンジンが候補に出すため、CPU側の追加対応は不要
- ブースト採用条件: 純益が閾値以上(**難: 300 / 普通: 500**)かつ通常召喚の最良より攻撃力が高い

**壁モード**(普通・難): ブースト込みの最大打点でも `相手最大打点 ≥ 自分の最大打点 + 600` なら、攻撃表示で出しても殴られてライフを失うだけなので、**守備力最大のモンスターを守備表示で召喚**する。

通常召喚時の表示形式: 原則攻撃表示。普通・難でライフ3000以下かつ「守備力 > 攻撃力」かつ攻撃力が相手最強未満なら守備表示。

### 3.3 バフ魔法(普通・難のみ、2ターン目以降)

| カード | 発動条件 |
|---|---|
| 草薙剣(N20) | 相手最強が自軍最強を上回るが差が500以内の時、自軍最強に付与(+500で逆転できる局面) |
| 軍配(N23) | 自軍3体以上かつ相手1体以下(総攻撃が通る局面) |

### 3.4 罠セット

セット可能な罠があれば無条件で先頭からセットする(空きゾーンがある限り)。

## 4. バトルフェイズ(`nextAttack`)

攻撃可能なモンスターを順に見て、最初に「良い対象」が見つかった攻撃を宣言する。相手の場が空なら全員で直接攻撃。

対象の優先度スコア(共通): 攻撃表示の相手 = `(自分の攻撃力 − 相手攻撃力) + 相手攻撃力×0.5`(除去価値+与ダメ)、守備表示 = `守備力×0.4`。

### 4.1 易・普通

素の値で勝てる相手のみ攻撃する。

- 攻撃表示の相手: `自分の攻撃力 > 相手の攻撃力` で攻撃。普通のみ、攻撃力1500以上の相手との**相打ち**も許容(主力同士の交換は損ではない)
- 守備表示の相手: `自分の攻撃力 > 守備力` で攻撃

### 4.2 難 — 守備の反撃(v1.6)回避

v1.6の戦闘反転により、リスクの所在が攻守で入れ替わった: **攻撃表示への攻撃は負けても攻撃側が破壊されない**(差分自傷のみ)、**守備表示への攻撃は守備力を下回ると攻撃側が破壊される**。hardの警戒ロジックもこれに合わせて攻守を交換している。

事前に計算する値:

| 変数 | 意味 |
|---|---|
| `oppCanReact` | 相手の手札が1枚以上 or 伏せ罠あり(=強化か罠で返してくる可能性) |
| `safeMargin` | 安全な打点差。**600**(この差を返すには相手は★7を捨てる必要がある)。伏せ罠がある時は砂かけ婆(-600)を見て**700** |
| `planBoost` | 自分が強化に回せる最大値(★3以下 or 鬼火のみ。主力は強化に切らない) |
| `desperate` | 自分のデッキ残り8枚以下かつ相手のデッキ枚数+1以下(膠着するとデッキ切れで自分が先に負ける。v1.6で6→8枚に前倒し) |

判断:

- **攻撃表示の相手**(ローリスク): 素で勝てる、または強化込み(`攻撃力 + planBoost`)で勝てるなら攻撃。1500以上との相打ちも許容。負けてもモンスターを失わないため安全マージンは要求しない
- **守備表示の相手で、相手がリアクション不能(`!oppCanReact`)または `desperate`**: 素で勝てる、または強化込みで勝てるなら攻撃
- **守備表示の相手で、相手がリアクション可能**(守備の反撃を警戒): 以下のいずれかを満たす時のみ攻撃
  1. `打点差 ≥ safeMargin`(十分な打点差)
  2. `打点差 + planBoost ≥ safeMargin`(自分の強化で安全圏に届く。実行は `decideBoost` が担当)
  3. `打点差 > 0` かつ相手の手札1枚以下かつ伏せ無し(対抗手段がほぼ無い)
  - 打点差がほとんどない壁には攻撃しない(反撃キル回避)
- メデューサ(R08)には攻撃力2000以上で攻撃しない(呪い効果の回避)
- 守備値の参照は `effectiveDef`(草薙剣・毒酒の守備力バフ込み。v1.6)

## 5. 戦闘強化

### 5.1 攻撃側(`decideBoost`)

捨てる候補を**手札価値の安い順**(鬼火は捨てて本望なので実質タダ扱い)に試す。

- **直接攻撃**: トドメが刺せる時のみ強化。難のみ例外で、相手ライフ4000以下なら鬼火(+1000)を気軽に切る
- **モンスターへの攻撃(易・普通)**: 素で勝っていれば温存。負け・相打ちなら安いカードでひっくり返す(易は★2以下 or 鬼火しか切らない)
- **モンスターへの攻撃(難)**: `nextAttack` と同じ `safeMargin` / `desperate` を再計算し、宣言済みの攻撃と連携する
  - 攻撃表示の相手(v1.6でローリスク化): 勝っていれば温存、負けていれば最小コストで逆転(マージン確保の強化は浪費)
  - 守備表示の相手(守備の反撃を警戒): 相手リアクション不能 or desperate なら最小コストで勝つだけ。リアクション可能なら **safeMargin に届く最小コストの強化**を使う(`nextAttack` が強化前提で宣言した攻撃を成立させる)。届かない場合でも、負けているなら最低限勝てる強化を使う

### 5.2 防御側(`decideReaction`)— 罠 or 強化の二択

想定被ダメージ(`expectedDmg`)と致死判定(`lethal`)を計算し、**罠を優先評価 → 使わない場合のみ強化を評価**する。

罠の評価順: 金縛り → アイギスの盾 → 神隠し → 砂かけ婆 → その他(背水の陣)。

| 罠 | 発動条件 |
|---|---|
| 金縛り(N24) | 致死 or 被ダメが閾値以上(易: 800 / 普通: 1200 / 難: 1500) |
| 神隠し(R14) | 致死 or 攻撃側の実効値が閾値以上(易: 1500 / 普通・難: 1800) |
| アイギスの盾(UR5) | 致死 or 相手の攻撃表示が多数(易: 2体以上、または1体で3500以上 / 普通・難: 3体以上、または2体で合計3500以上) |
| 砂かけ婆(N28) | -600で戦闘がひっくり返る時、または直接攻撃の軽減(致死 or 1800以上) |
| 背水の陣(R12) | 致死 or 被ダメ閾値以上(易: 1000 / 普通・難: 1500) |

強化の評価(罠を使わなかった場合のみ、安い順):

- 攻撃表示の防御側: 上回れば自分のモンスターを守りつつ差分を相手ライフに跳ね返せる(v1.6: 攻撃側は破壊されない)ので、負けている戦闘をひっくり返せるなら強化(易は安いカードのみ)。難のみ、攻撃力1500以上の主力の**相打ち回避**にも使う
- 守備表示の防御側(v1.6: **守備の反撃**): 守備力が攻撃力を上回れば**攻撃側を破壊**できる。反撃キルが成立するなら安いカード、または攻撃側が1500以上なら高コストでも強化する。同値で止めるだけ(破壊なし)なら安いカード限定。ぬりかべは守備表示の味方への強化で+800になるため実質タダ扱い

## 6. 罠発動・効果対象

### 召喚トリガー罠(`decideTrap`)

落とし穴(SR10)のみ対象。召喚されたモンスターの攻撃力が閾値以上(易: 1400 / 普通: 1600 / 難: 1700)、または自軍最大打点+500を超える時に発動する。

### 効果対象の選択(`decideTarget`)— 難易度共通

| 効果元 | 選択基準 |
|---|---|
| 雪女(N11)・九尾の狐(R07) | 最大打点の相手を守備表示に寝かす |
| 卑弥呼(N17)・織田信長(SR3) | 先頭の伏せでよい(情報量に差がない) |
| 浦島太郎(N18) | 回収価値の評価: モンスター=攻撃力 / 天罰=2600 / 鬼退治=2000 / その他魔法罠=1200 |
| 安倍晴明(R04) | サーチ優先表: 天罰 > 鬼退治 > 強制送還 > 黄泉返り > 金縛り > 落とし穴 > 毒酒 > 神隠し > アイギス > 払い清め > 砂かけ婆 > 人魚の肉 |
| ヴァルキリー(SR5) | 墓地の攻撃力最大(★3以下)を蘇生 |
| 背水の陣(R12) | 手札の守備力最大を壁に |

## 8. 検証方法

CPU同士の総当たり自動対戦で回帰を確認する:

```bash
cd frontend && npx tsx scripts/simulate.ts 500            # 全対戦カード
cd frontend && npx tsx scripts/simulate.ts 600 "normal vs hard"  # 絞り込み
cd frontend && npx tsx scripts/diag.ts 1000               # 詳細メトリクス(normal vs hard)
```

simulate.ts はクラッシュ・無限ループ・不変条件(カード総数)の検証と難易度間勝率、diag.ts は敗因内訳・ブースト召喚・供物経由率・守備召喚・UR召喚・先攻勝率を出力する。閾値を調整したら必ず回すこと。100〜200戦の勝率は±7pt程度ぶれるため、有意差の判断は600戦以上で行う。

現状の実測値(v1.6):

- easy vs hard ≒ 35 : 65
- normal vs hard ≒ 47 : 53(1000戦)
- デッキ切れ決着は約7%、平均17.4ターン(8.7巡)。戦闘反転で膠着しやすく、
  強行弁をデッキ残り8枚に前倒しして抑制している
