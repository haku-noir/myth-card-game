# 神話カードゲーム Webアプリ 設計ドキュメント v1.1

仮称: **レベル&リリース**

---

## 0. 確定事項

| 項目 | 決定内容 |
|---|---|
| PvP通信 | オンライン（ルームコード）。ルーム設計は4〜8人対応を視野に入れる |
| ブースタードラフト人数 | 初期実装は2人専用。内部設計はN人対応（4〜8人への拡張を考慮） |
| CPU難易度 | 易 / 普通 / 難 の3段階 |
| デプロイ環境 | ローカルDockerのみ |
| デッキ保存 | 作成済みデッキをDB保存し、パック開封をスキップしてゲーム開始可能 |

## 1. 全体方針

### 技術スタック

| 層 | 採用技術 | 理由 |
|---|---|---|
| フロントエンド | React + TypeScript + Vite | SPA、型安全、高速HMR |
| スタイリング | Tailwind CSS | ユーティリティファーストで素早くUI構築 |
| 状態管理 | Zustand | 軽量、ゲームステートに適合 |
| リアルタイム通信 | Socket.io | PvP/ドラフト用の双方向通信 |
| バックエンド | Node.js + Express + TypeScript | シンプル、Socket.ioと相性良 |
| DB | SQLite + Prisma | 軽量、Docker単体で動作、デッキ保存に使用 |
| コンテナ | Docker + docker-compose | フロント/バックを分離 |

### Docker構成

```
docker-compose.yml
├── frontend  (port 3000) ── Vite dev server
└── backend   (port 4000) ── Express + Socket.io + SQLite
```

ローカル専用のため本番向けnginx設定は不要。

#### ⑥ ドラフト画面

**シールド戦** `/draft/sealed`
- PvPルームを作成/参加（1〜2人）
- 全員が揃ったら各自でパック開封フローへ
- 各自デッキ構築後、全員確定でゲーム開始

**ブースタードラフト** `/draft/booster`

```
[ドラフトルーム]
参加者: 2/2  パック: 1/4  ピック: 4枚目

┌───────────────────────────────────────┐
│  回ってきたパック (残り7枚)            │
│                                       │
│  ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐   │
│  │  │ │  │ │  │ │  │ │  │   │
│  └──┘ └──┘ └──┘ └──┘ └──┘   │
│  (残り2枚は省略表示...)              │
│                                       │
│  あなたのピック済み: 桃太郎 他3枚     │
│         ← 1枚選んで左の席に回す →    │
└───────────────────────────────────────┘
```

**ブースタードラフトのフロー詳細（2人用、N人対応設計）:**

```
セットアップ:
  - ルームに N 人が着席（現在は 2 人固定）
  - 各プレイヤーが1パック(10枚)を開封

ピックフェイズ（1パック分）:
  - 全員が同時に現在のパックから1枚選択
  - 全員確定したら、各自の残りパックを「左の席（seatIndex+1）%N」へ渡す
  - パックが空になるまで繰り返す
  - ※2人の場合: 10枚パックを互いにやり取り、各5枚獲得

パック進行:
  - パック1: 時計回りに渡す
  - パック2: 反時計回りに渡す
  - パック3: 時計回り
  - パック4: 反時計回り
  - 4パック完了 → 合計20枚

デッキ確認フェイズ:
  - ドラフトした20枚が全てデッキに入った状態で表示
  - 並び替えのみ可（カード枚数の変更は不可）
  - 「確定する」でゲーム開始待機

全員確定 → ゲーム開始
```

## 4. データモデル

### カード型

```typescript
// frontend/src/types/card.ts
type Rarity = 'N' | 'R' | 'SR' | 'UR';
type CardType = 'monster' | 'magic' | 'trap';

interface Card {
  id: string;           // "N01", "R04", "SR1", "UR1" など
  name: string;
  type: CardType;
  rarity: Rarity;
  stars?: number;       // モンスターのみ 1〜8
  atk?: number;
  def?: number;
  effectText: string;   // 効果なし = ""
}
```

### 保存済みデッキ型

```typescript
// frontend/src/types/deck.ts
interface SavedDeck {
  id: number;           // DBの主キー
  name: string;
  cardIds: string[];    // 20枚のカードID配列（重複あり可）
  createdAt: string;
  updatedAt: string;
}

interface DeckSummary {
  id: number;
  name: string;
  cardIds: string[];
  rarityCount: { N: number; R: number; SR: number; UR: number };
  starDistribution: Record<number, number>; // { 1:4, 2:3, ... }
  createdAt: string;
}
```

### ゲーム状態型

```typescript
// frontend/src/types/game.ts
type Phase = 'level_up' | 'draw' | 'main' | 'battle' | 'end';
type DisplayMode = 'attack' | 'defense';

interface FieldMonster {
  card: Card;
  displayMode: DisplayMode;
  hasAttacked: boolean;
  changedDisplayThisTurn: boolean;
  destroyAtEndOfTurn: boolean;  // メデューサ効果
}

interface PlayerState {
  id: string;
  name: string;
  life: number;                         // 初期6000
  level: number;                        // 先攻初期1 / 後攻初期2
  hand: Card[];
  deck: Card[];                         // シャッフル済み積み残し
  graveyard: Card[];
  monsters: (FieldMonster | null)[];    // 長さ5
  traps: (Card | null)[];              // 長さ3（セット済み）
  setThisTurn: Set<string>;             // このターンにセットした罠ID
  isFirstTurn: boolean;                 // 先攻第1ターンフラグ（攻撃不可）
}

interface PendingAction {
  type: 'trap_activate_prompt';
  triggerDescription: string;
  trapCard: Card;
  playerId: string;                     // 発動を問われているプレイヤー
  timeoutAt: number;                    // タイムスタンプ
}

interface GameState {
  phase: Phase;
  turnPlayer: string;                   // playerId
  turnCount: number;
  players: [PlayerState, PlayerState];  // [0]=先攻, [1]=後攻
  log: LogEntry[];
  pendingAction?: PendingAction;
  winner?: string;                      // 決着したらplayerId or 'draw'
}

interface LogEntry {
  turn: number;
  phase: Phase;
  message: string;
}
```

## 7. CPU AI設計

### 難易度別行動方針

| 難易度 | 召喚 | 攻撃 | 罠セット | 罠発動 |
|---|---|---|---|---|
| 易 | レベル以下で最強1体のみ | 勝てる相手のみ攻撃 | 手札の罠をランダムセット | 効果が確実な時のみ |
| 普通 | リリースチェーン1回まで利用 | 戦況評価して攻撃/直接攻撃優先 | 適切なタイミングでセット | 基本的な得失判断 |
| 難 | 最長リリースチェーンを探索 | 全体最適を計算して攻撃順を決定 | 状況に応じて温存も | ライフ差・手札数を加味した高度な判断 |

### 行動評価スコア

```typescript
// cpuService.ts
function evaluateBoard(myState: PlayerState, oppState: PlayerState): number {
  const myPower = myState.monsters
    .filter(Boolean)
    .reduce((sum, m) => sum + (m!.displayMode === 'attack' ? m!.card.atk! : m!.card.def!), 0);
  const oppPower = oppState.monsters
    .filter(Boolean)
    .reduce((sum, m) => sum + m!.card.atk!, 0);
  const lifeDiff = (myState.life - oppState.life) * 0.05;
  const handBonus = myState.hand.length * 50;
  return myPower - oppPower + lifeDiff + handBonus;
}
```

### リリースチェーン探索（普通・難）

```
入力: 手札、現在のレベル、フィールドのモンスター
出力: 最大星のモンスターを召喚できるリリースチェーン

アルゴリズム:
1. 手札のカードをDFS探索
2. (現在レベル + チェーンで出したモンスターの星) が次に召喚できる星の上限
3. 最終的に最大攻撃力のモンスターを召喚できるパスを返す
```

## 9. ゲームエンジン設計

ゲームロジックはフロントエンド（`useGameEngine.ts`）に実装。
CPU戦はクライアントサイドで完結。PvP時はサーバーが状態同期の仲介を担う。

### ターン状態遷移

```
IDLE
  ↓ startGame()
LEVEL_UP      ─ 自動: level += 1
  ↓
DRAW          ─ 自動: deckからカードを引く。引けなければ → GAME_END(敗北)
  ↓
MAIN_PHASE    ─ プレイヤー入力待ち（CPU戦は evaluateTurn() を呼ぶ）
  ↓ endMainPhase()
BATTLE_PHASE  ─ 先攻第1ターンはスキップ
  ↓ endBattlePhase()
END_PHASE     ─ destroyAtEndOfTurn のモンスターを処理。「ターン終了時まで」の効果をリセット
  ↓
LEVEL_UP (相手ターン) ...
```

### 効果処理フロー（チェーンなし）

```
1. プレイヤーがアクション宣言（召喚/攻撃/魔法発動）
2. 罠チェック: 相手の伏せカードが発動条件を満たすか確認
   - 満たす → 相手に「発動しますか？」prompt（30秒タイムアウト）
   - 発動する → 罠効果処理 → アクション処理（アクションは中断/継続を罠テキストに従う）
   - しない/タイムアウト → アクション処理
3. アクション完了後、召喚時効果が存在する場合は即時解決
```
